## Trace and mandatory regressions — before implementation

User action: import Enhancing Mindmap or Markmind basic Markdown and compare the source editor with the resulting board. Trace: format marker -> mindmapOutlineAdapter -> parseMindmapOutline -> deterministic rightward tree layout -> BoardBuilder cards/curved edges -> import preview/publication.

Both plugins persist mindmap-plugin: basic with headings/lists. Neither that file nor the existing reader provides original pixel coordinates, branch colors, node fonts, border widths or the current viewport. Display-mode and mindmap-theme properties are plugin-specific runtime presentation instructions. They are reported, not interpreted as coordinates. Original layout cannot be recovered by matching Markdown alone; source-editor layout/rendering must be evaluated independently.

Planned narrow repair: retain Markdown hard-break trailing spaces in list labels and continuation text. Existing trim removes them and changes native Markdown appearance. Do not invent a source layout or enable rich mode.

Mandatory unit regressions: hard line breaks, inline code/emphasis/wikilinks/math/table/fenced code bytes; heading/list hierarchy; folded marks; node count and no overlaps; every nonempty line represented; both parsed properties and text marker detection; rich mode rejected; source bytes unchanged; existing import-mindmap and common regressions; TypeScript/lint/diff check.

Mandatory native checks (pending; parent owns): install Enhancing Mindmap 0.2.5 or Markmind 3.7.4 in isolated QA profiles, open the authored marked note and toggle its source editor; compare hierarchy/text independently from layout/theme; original-node and board-node edit; preview/cancel/source preservation/reopen; Markdown hard line break rendering. Markmind rich must be produced by the editor's basic-to-rich conversion command and saved with provenance before its JSON structure can be audited.
## Optional source-view handoff — trace before implementation

The parent can capture normalized source DOM/model facts from an already-open Enhancing Mindmap view. This adapter never imports or starts that plugin. Proposed ImportContext.mindmapLayout is unknown at the shared boundary; a pure reader verifies exact sourceText, every parsed node's sourceLine/text, complete parent-child edge coverage, finite bounded geometry, and a narrow allowlist of existing style fields, including bounded cornerRadius.

An invalid, stale, incomplete or ambiguous snapshot is refused and the offline layout remains an explicit approximation. A valid snapshot supplies positions, sizes, fonts, colors and branch colors/widths; sampled straight-route connectors retain the source path samples; the remaining appearance approximation uses reason appearance, not a false new-layout claim. Original table/outline modes are not Canvas mindmaps.

Mandatory checks: valid geometry/style capture; source staleness; sourceLine/text mismatch; missing/duplicate/extra cards or branches; nonfinite/unbounded geometry; unsafe/unsupported style/waypoints; no partial snapshot use; deterministic tree fallback; source bytes unchanged. Parent must separately validate DOM coordinate units, capture at nondefault zoom, source-mode/theme changes and actual original-vs-imported render.
